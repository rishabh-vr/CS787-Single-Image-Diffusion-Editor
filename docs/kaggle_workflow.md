# Running steps 3–7 on Kaggle (free)

Steps 1–2 (notebook 00 and the Phase 4 reproduction) ran on Colab; their results are on Google Drive.
Everything after that runs on **Kaggle**: free, ~30 GPU-hours per week, **two T4s per session**, sessions of up
to 12 h that keep running in the background. Notebooks: `notebooks/kaggle/` (generated by
`scripts/make_kaggle_notebooks.py`; edit that script, not the .ipynb files).

## One-time setup
1. Create a Kaggle account and **verify your phone number** (Settings → Phone verification). Without it there is
   no GPU and no Internet in notebooks.
2. Import each notebook: kaggle.com → **Create → New Notebook → File → Import Notebook → Link** and paste
   `https://github.com/rishabh-vr/CS787-Single-Image-Diffusion-Editor/blob/main/notebooks/kaggle/<name>.ipynb`
   (or download the file from GitHub and use the *File* tab). Give each notebook its own name (K10, K11, ...).
3. In each notebook, right panel → *Session options*: **Accelerator = GPU T4 x2** (K13: *None*), **Internet = On**.

## Running a notebook
- **Save Version → Save & Run All (Commit) → Save.** It runs in the background; you can close the browser.
- Watch it: the notebook's page → *Versions* / *View Active Events* → **Logs**. Every 2 min there is a line per
  experiment: `phase7_ood: 412/1230 samples (33%) | 2.4/min | ETA 5h41m`, plus which task runs on which GPU.
  (Run interactively instead and you get live progress bars in the cell, but the session ends when you leave.)
- The result is the version's **Output**: one file `cs787_<name>.zip` (+ `logs/`).
- Each notebook stops by itself at `SESSION_HOURS = 1.9` (1 h 54 min) and zips what it has, so a run never
  goes past 2 hours and nothing finished is lost. **To continue:** *Add Input → Your Work →* the same notebook (latest version) → Save Version
  again. Finished samples are never recomputed.

## The notebooks (each finishes in < 2 h: hard stop at 1 h 54 min)
| Notebook | Step | Reduced run | Time |
|---|---|---|---|
| K10_run_jobs | 3 | Phase 7 OOD: Set A + Set B × 6 seeds; Phase 9 ablations without the two T = 40 jobs, 4 images × 4 seeds; Phase 8 "ours" × 10 seeds | ≈ 1.5 h |
| K11_sinddm | 4 | SinDDM 3 OOD images × **3k steps** (≈ 1 T4-h each, matched to our method's compute), sampled at 1.5k / 3k + the 3 pretrained models, 20 samples each | ≈ 1.6 h |
| K12_lora | 5 | 8 LoRAs × **400 steps**, two at a time; 15 samples each | ≈ 1.2 h |
| K13_evaluate | 6 | metrics for everything, ≤ 20 samples per image (CPU, no GPU quota) | ≈ 1–1.5 h |
| K14_applications | 7 | retargeting / tileable (optional) | ≈ 0.5 h |

**Deviation from the plan (2026-11-15):** sample counts and baseline training budgets are cut so that every
notebook runs in under 2 hours (full plan ≈ 30 GPU-hours, reduced ≈ 6). The cuts only *truncate* seeds / images /
jobs (`JOB_LIMITS` in K10), so outputs and config hashes are unchanged and a later run with larger limits just adds
the missing samples. Consequences for the report: wider confidence intervals; SinDDM is compared at a matched
small compute budget (≈ 1 GPU-hour per image) plus its fully trained pretrained models, not at a reduced 20k-step
schedule; the T = 40 (AB3) settings are not run (the Phase 4 T = 40 job was also not reached on Colab), so
the T × η ablation covers only T = 10 with η = 0 and 1.

## How it works
- `sidx.gpupool.job_tasks` splits every job into image chunks; `run_pool` runs them on all GPUs
  (`CUDA_VISIBLE_DEVICES` per worker), next chunk to the first free GPU, each worker's log in `logs/`.
- Progress = finished files on disk (sample PNGs; SinDDM `progress.json` with step/loss; LoRA's step counter in
  its log; evaluator `progress.json`), shown by `sidx.progress.Bars`: tqdm widgets live, plain lines in a
  background run (`KAGGLE_KERNEL_RUN_TYPE=Batch`).
- Outputs and config hashes are identical to the Colab runner, so Colab and Kaggle results mix freely.
